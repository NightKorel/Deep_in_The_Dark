# 潛淵 — 檔案地圖（給編輯者/Claude 快速定位用）

> 目的：一看就知道「哪個功能在哪個檔、哪個函式」，不用每次翻整包程式碼，省時間省 token。
> **規則：改動或新增功能後，要順手更新這份地圖；每次動工前也要先看這份地圖找位置。**（見 CLAUDE.md）
> ⚠️ **2026-08-14 納可指示：目前處於藍圖討論階段，一切更改僅限設計討論，不動遊戲程式或現有機制。**

## 載入順序（index.html）
`01_資料庫` → `02_介面共用與存讀檔` → `03_開場劇情` → `04_避難所` → `05_深潛` → `06_戰鬥` → `07_成就` → `08_賭場` → `09_劇情記錄` → `10_戰鬥AI`

## 各檔案負責什麼

### 01_資料庫.js — 純資料（沒有邏輯）
角色 `CHARACTERS`、技能 `SKILLS`、狀態常數、怪物 `MONSTERS`＋`MONSTER_SKILLS`、
圈層資料 `LAYERS_META`／`LAYER_BOSS`／各層怪物池／菁英組合 `ENEMY_GROUPS_LAYERx`、
節點配置 `LAYERx_NODE_CONFIG`、奇異地形 `ODDITY_EVENTS`、代價交換 `COST_EXCHANGE_OPTIONS`、
隨機事件 `RANDOM_EVENTS`、寶藏/商店、食材料理 `FOODS`、藥材魔藥 `HERBS`/`POTIONS`、
遺物 `RELICS`＋分類 `RELIC_CATEGORIES`＋資料驅動助手 `relicSum`/`relicMax`、全局增益 `GLOBAL_BUFFS`。
- 要調數值、加怪/技能/遺物/事件/料理 → 大多在這裡。
- **遺物只從成就拿**（見 07）：深潛中的節點/事件/商店都不再給遺物，只給潛晶或增益。
- **🔮`ODDITY_EVENTS` vs ❔`RANDOM_EVENTS` 定位（別搞混）**：🔮＝安全強化/補給（只給 buff/回血、零風險、不給潛晶）；
  ❔＝有賺頭但有風險（潛晶/藥/增益＋受傷/戰鬥/空手）。加新內容照這分工放（規則詳見 `ODDITY_EVENTS` 上方註解）。

### 02_介面共用與存讀檔.js — 共用邏輯＋存讀檔＋各種選單
`gameState`（存檔的資料結構）、小工具（randInt/chance…）、角色數值計算（getCharacterMaxHp…）、
畫面切換 `showScreen`/`updateTopStatusBar`、通用彈窗 `openGenericModal`、改名、設定、
**作弊選單 `openCheatModal`＋各 cheat 函式**、通知 `systemToast`、
**對話劇情層 `playDialogue`/`showNextDialogueLine`（劇情記錄 `recordStoryLog` 也在這）**、
存讀檔 `collectSaveData`/`applySaveData`、入口 `initGame`。
- 要改存檔欄位 → `gameState` ＋ `collectSaveData` ＋ `applySaveData` 三處一起改。
- 要加對話 → 用 `playDialogue(lines, onComplete, logInfo?)`。
- **劇情逐字動畫**：`typeDialogueText`（逐字/整句）＋`finishTypewriter`（點一下秒顯示）＋`revealDialogueControls`
  （字跑完才擺選項/輸入框）；速度常數 `TYPEWRITER_SPEED`。開關在 `gameState.settings.typewriter`（設定選單）。
- **Auto 自動下一句**：`cycleDialogueAuto`（關/慢/中/快循環，按鈕 id `dialogue-auto-btn`）＋`scheduleAutoAdvance`
  ＋`renderDialogueAutoBtn`；延遲常數 `AUTO_DELAYS`，狀態存 `gameState.settings.autoMode`。
  計時器統一由 `clearDialogueTimers` 收乾淨（`showNextDialogueLine` 與作弊跳教學都會呼叫）。

### 03_開場劇情.js — 新手開場
21 段開場（墜落→教學岔路→固定劇本教學戰鬥→認識 K/V→命名→世界觀→轉入避難所）。
`startOpeningStory`→`continueOpeningAfterFight`→`continueOpeningAfterNaming`→`finishOpeningStory`；
作弊 `cheatSkipTutorial`。

### 04_避難所.js — 避難所各設施
工坊（**歷練與技能頁** `showWorkshopUpgradeScreen`：升歷練 `upgradeTrainLevel`＋解鎖技能 `unlockSkill`＋一鍵升歷練 `oneClickTrainUp`/`doOneClickTrainUp`；魔藥間製藥）、
家（煮飯/技能遺物/整備出發/補血藥）、
**整備出發＋圈層下拉選單 `showDepartScreen`/`departLayerChoiceHtml`/`confirmDepart`**、
圖鑑（怪物/料理/魔藥）、回程結算 `applyShelterReturn`。
- **技能遺物頁（原「技能管理」）`showSkillManagementScreen`/`showSkillManagementForChar`**：
  上半段技能裝備、下半段遺物裝備 `relicSectionHtml`/`relicInventoryHtml`（分類篩選 `setRelicFilter`、
  搜尋 `onRelicSearchInput`、裝/拆 `equipRelicToChar`/`unequipRelicFromChar`）。遺物是永久的，裝到角色身上就一直在。

### 05_深潛.js — 探索（走地圖）
圈層工具（依 `activeDive.layer` 取節點/怪物池/Boss；`getMonsterLayer`/`getFoodLayer`/`getHerbLayer`/`getLayerThemeColor` 反查所屬層與主題色）、出發初始化 `startNewDive`、
畫面渲染 `renderDiveScreen`（含 Boss 門前劇情）、節點分派 `chooseNode`、
各節點：戰鬥/休息/奇異地形/代價交換/隨機事件/寶藏/商店、
**Boss 戰後劇情 `handleLayer1BossVictory`/`handleLayer2BossVictory`/`handleLayer3BossVictory`**（由 `handleBossVictory` 依 `activeDive.layer` 分派）、
作弊 `cheatCompleteLayer1`/`cheatCompleteLayer2`/`cheatCompleteLayer3`。
- **怪物難度：層倍率（2026-08-13）**：怪的實際血量/傷害＝「基礎模板 × 該層倍率」。基礎＝01 的 `MONSTERS[].hpRange`
  ＋`MONSTER_SKILLS[].dmgRange`（只管同層內相對手感）；層倍率＝01 的 `LAYER_MONSTER_HP_MULT[n]`／`LAYER_MONSTER_DMG_MULT[n]`
  （`getLayerHpMult`/`getLayerDmgMult`，第一層=1.0）。血量在 06 `buildEnemyInstance` 乘、傷害在 06 `dealDamageToAlly` 乘；小怪/菁英/Boss 都乘。
  成長（2026-08-13 精簡版）：角色靠**歷練等級** `trainLevel` 一條軸帶動血量/普攻/技能傷害，
  倍率 `getTrainMultiplier`＝`TRAIN_GROWTH_RATE`(1.09)^(歷練-1)；血量 `getCharacterMaxHp`、普攻/技能 `getCharacterWeaponMultiplier`、治療 `getCharacterHealMultiplier` 都吃它。
  潛晶花費：升歷練 `getTrainUpgradeCost`(15 起×1.5)、解鎖技能 `getSkillUnlockCost`(`SKILL_UNLOCK_COSTS`=[0,40,75,120])；技能解鎖狀態＝角色 `unlockedSkills`（`isSkillUnlocked` 讀它）。
- **加新圈層的步驟**（第三層已照此接上，之後第四層比照）：01 加 `LAYERn_MONSTER_POOL`／`LAYER_BOSS[n]`／
  `LAYER_MONSTER_POOLS[n]`／`LAYERS_META[n]`／`LAYER_REWARD_MULT[n]`／`LAYER_FIND_MULT[n]`／`LAYER_MONSTER_HP_MULT[n]`／`LAYER_MONSTER_DMG_MULT[n]`／`LAYERn_NODE_CONFIG`＋`LAYER_NODE_CONFIGS[n]`、
  把 `MAX_LAYER` 加一；05 的 `getUnlockedLayers`（解鎖條件）、`handleBossVictory`（加分派）、新 `handleLayerNBossVictory`、
  Boss 門前劇情（`renderDiveScreen` 內、旗標 `bossNDoorShown`）、作弊 `cheatCompleteLayerN`；02 的 `storyFlags`（`layerNCleared`/`bossNDoorShown`）＋作弊選單按鈕。
  （註：第四層起節點改「帶隨機性」動態生成，不再寫死 `LAYERn_NODE_CONFIG`——見 設計文件/第四層規劃.txt。）

### 06_戰鬥.js — 回合制戰鬥引擎
建立戰鬥 `startBattle`、回合流程 `beginRound`/`tickStatusEffectsAll`、敵人 AI `chooseEnemyIntent`/`executeEnemySkill`、
**傷害計算 `damageCalc`/`dealDamageToAlly`/`dealDamageToEnemy`**、玩家行動、
**補血藥 `battleDrinkPotion`（直飲30%）/`battleApplyPotion`（外敷HoT，第二層Boss後解鎖）**、戰鬥結束/獎勵、
畫面渲染 `renderBattleScreen`、**視覺反饋 `flashUnit`/`spawnFloatingNumber`（飄傷害數字）**。
- **敵人 AI 通則（納可拍板）**：`chooseEnemyIntent` 預設是「冷卻好的技能裡隨機挑一個」＋目標隨機（唯一例外：有人格擋會優先打格擋者）。
  只有特別指定的怪才寫定向 AI（如第四層章魚鎖血量最低/最高、被控 K 會補血）——沒特別指定就維持隨機。
- **狀態圖示（血條旁 `statusIconHtml`）**：我方混亂 `confuseTurns`→😵‍💫、敵方蓄勢 `chargeReady`→⚡；
  另有流血🩸/中毒🟣/震懾🫨/護盾🛡️/格擋/蓄力/減傷等。第三層新機制 handler（`confuse-chance-all`/`heal-all-enemies`/
  `buff-ally-charge`/`summon-copy`/`summon-temporary`/`multi-random-hits` 的 `hitsRange`+`allowRepeat`）都在 `executeEnemySkill` 內。

### 07_成就.js — 成就（＋遺物來源）
`ACHIEVEMENTS`（清單，每條含 `relic`＝對應遺物、`hint`＝謎語提示）、`checkAchievements`（統一解鎖＝同時發遺物）、
`openAchievementsModal`（一覽，未解鎖只顯示圖示+提示、名字/描述遮 ???）。
- **遺物擁有狀態不另存清單**：`ownedRelicIds`（已解鎖成就對應的遺物）／`equippedRelicIds`（已裝在角色身上的）／
  `inventoryRelicIds`（已擁有未裝備＝可裝清單）都是即時從成就＋角色 `relics` 推出來。
- 第一次拿遺物時 K 的解說 `RELIC_INTRO_LINES`＋`flushRelicIntro`（戰鬥中不播、回安全畫面補播）。
- **加成就 → 往 `ACHIEVEMENTS` 加一條，寫好 `check()`、`hint`、並在 01 的 `RELICS` 加一個對應遺物、填 `relic`。**
- **加遺物 → 只改 01 的 `RELICS`（含 `cat` 分類）；戰鬥效果是資料驅動 `relicSum`/`relicMax`，
  同一個 `effect.type` 不用動戰鬥碼，全新的 type 才要去 06 接。**

### 08_賭場.js — 賭場（H）
節點賭場（賭潛晶）＋避難所賭場（代幣）、共用下注列、各款遊戲（翻礦盤/逼深骰/騙子骰/深淺牌/破譯/記憶迴光）、
解鎖判定 `isShelterCasinoUnlocked`。詳規見 `設計文件/賭場設計.txt`。

### 09_劇情記錄.js — 劇情回顧
從 `gameState.storyLog`（玩過才有）讀出主線段落，選單 `openStoryLogModal`／看單段 `showStoryLogScene`。
- 要讓某段對話進回顧 → 在該 `playDialogue` 第三參數傳 `{ id, title, order, append? }`。

## 常見「我想改 X，去哪找？」
- 某個數值（血量/傷害/掉落/價格） → `01_資料庫.js`
- 某段劇情台詞 → 開場在 `03`；Boss 門前/戰後在 `05`；其餘節點事件文字多在 `01`(資料) 或 `05`(觸發)
- 存檔壞了/加存檔欄位 → `02` 的 `gameState`＋`collectSaveData`＋`applySaveData`
- 戰鬥手感/傷害/視覺 → `06`
- 賭場 → `08`（＋`設計文件/賭場設計.txt`）
- 成就 → `07`
- 出發/避難所設施 → `04`
- 戰鬥 AI「小艾」（AI 玩家暱稱，聰明玩家/未來被控 K 共用） → `js/10_戰鬥AI.js`

## 開發工具（scripts/，不進遊戲、只給開發者跑，零 AI 額度）
- **`scripts/冒煙測試.js`**：常駐維護核心測試——一鍵驗證「遊戲沒被改壞」（資料完整性＋三層劇情＋各層戰鬥）。每次改完都跑。
- **`scripts/難度檢查.js`**：單場戰鬥難度模擬——各層小怪/菁英/Boss 各打 N 場，出「勝率/剩血」表。跑兩條：裸模型（只普攻）＝下限、聰明 AI（用 `js/10_戰鬥AI.js`）＝上限。
- **`scripts/全流程模擬.js`**：整個經濟循環模擬——AI 玩家「小艾」像真玩家從零開始一層層推（下潛→打整層→回避難所升級→再下潛），報告「每層打幾趟過關、何時升級、卡在哪」。用來校準難度與成長曲線。
  - **小艾**＝AI 玩家的暱稱（納可取的），我們的重要測試員：不花額度、跑得比誰都勤，戰鬥決策就是 `js/10_戰鬥AI.js` 那份。
