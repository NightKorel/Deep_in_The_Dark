# 給 Claude 的工作規則（潛淵專案）

這個檔案是專案的固定規則。**每次工作前先讀這裡，每次工作都要照這裡做。**
使用者（納可）是程式小白，請用白話說明，不要假設對方懂技術細節。

---

## ⭐ 每次「更新」都必做的三件事

這裡的「更新」＝任何一次改到遊戲內容或檔案的工作。做完主要工作後，依序完成：

### 1. 寫更新日誌
- 檔案：`更新日誌.txt`
- **最新的內容寫在檔案最前面（最上面），不是最後面。**
- 每筆包含：日期、這次做了什麼（用白話）。

### 2. 全部備份
- 執行 `bash scripts/備份.sh` 即可自動完成，它會：
  - 把目前遊戲內容整包複製成一個資料夾，放進 `備份/`。
  - `備份/` 裡**只保留最新 3 個**備份。
  - 第 4 個（含）以上的更舊備份，自動移進 `備份/更舊的/`。
- 若不用腳本手動做，也要遵守上面同樣的規則。

### 3. 更新要求清單
- 檔案：`納可要求清單.txt`
- 使用者給的每個指令都要先登記成一條。
- **還沒做完的，放在檔案最前面（最上面）。**
- **做完的，移到檔案最後面（最下面），並在該條前面標記 `✗`**（表示已完成/已劃掉）。

### 4. 存到 GitHub（雲端環境特別重要）
- 這是雲端環境，只有 push 到 GitHub 的東西才會保留，本機資料夾會被回收。
- 所以每次更新後（含備份資料夾），都要 `git add -A`、commit、push 到指定分支。

---

## ⭐ 納可的長期授權（可以主動做事）

納可已明確授權，不用每件事都問：

- **看到可以優化／可以做得更好的地方，就直接動手**。只有在「真的不確定納可的意思」時才停下來問。
- **可以自己發想、加入新內容與新細節**（例如她一直想要的**成就系統**——成就可以自己設計、
  自己持續增加更新，不用等她開口）。
- **遺物與隨機事件：想到就可以加**，盡量有趣、這類東西永遠不嫌多；但**不要為了湊數量而做重複、
  雷同的東西**（新的要跟既有的有明顯差異）。
- **唯一紅線：不要更動納可明確指定過的東西**——包含既有角色／技能／怪物的設定與數值、劇情台詞、
  已定案的機制與工作流程規則，以及她指定過的功能規格。要改這些才需要先問。
- 主動加的東西一樣遵守下面「穩定版 vs 開發中」規則：先在 `開發中/` 做，完工測好才進根目錄。
- 做完仍要照最上面「每次更新必做的事」：寫日誌、備份、更新要求清單、push 到 main。

## ⭐ 穩定版 vs 開發中（GitHub Pages 上線規則）

GitHub Pages 會把 `main` 分支**根目錄**的內容變成公開可玩的網頁；玩家點的就是這個。

**判斷標準只有一個：這個版本會不會崩潰／壞掉當掉？**（不是「功能有沒有全部做完」）

- **不會崩、跑得起來 → 放根目錄（穩定版）**。就算功能還沒全部做完，只要能正常玩、不會壞，
  就放上去給玩家/測試員玩。
  - 目前玩家都是納可的朋友測試員，所以**作弊選單要保留**（跳教學／通關第一層／全體升等／
    測試第二層等）。
- **可能會崩／正在動刀改到一半 → 暫時放 `開發中/` 資料夾**。等它跑得起來、不會崩，
  再整包複製覆蓋回根目錄成為新的穩定版。
  - `開發中/` 只是「暫存還在弄、可能會壞的東西」的地方；沒有這種東西時，這個資料夾可以不存在
    （要用時再從根目錄複製一份出來改）。
- **推送位置**：直接 commit / push 到 `main`（納可已開好權限），不用另開分支。
- 根目錄有 `.nojekyll`，確保 Pages 原樣提供所有檔案（含中文檔名/資料夾）。

## 專案技術備註

- 純前端遊戲（HTML + CSS + 原生 JavaScript），無框架、無建置流程。
- 直接用瀏覽器打開 `index.html` 就能執行；改完重新整理瀏覽器即可看到結果。
- 檔案結構與系統說明見 `README.md`。
- 改程式前先讀對應檔案開頭的區塊註解（原作者的中文註解很詳細）。
