# 給 Claude 的工作規則（潛淵專案）

這個檔案是專案的固定規則。**每次工作前先讀這裡，每次工作都要照這裡做。**
使用者（納可）是程式小白，請用白話說明，不要假設對方懂技術細節。

---

## ⭐ 每次「更新」都必做的三件事

這裡的「更新」＝任何一次改到遊戲內容或檔案的工作。做完主要工作後，依序完成：

### 1. 寫更新日誌
- 檔案：`更新日誌.txt`
- **最新的內容寫在檔案最前面（最上面），不是最後面。**
- 每筆包含：日期、這次做了什麼（用白話）。

### 2. 全部備份
- 執行 `bash scripts/備份.sh` 即可自動完成，它會：
  - 把目前遊戲內容整包複製成一個資料夾，放進 `備份/`。
  - `備份/` 裡**只保留最新 3 個**備份。
  - 第 4 個（含）以上的更舊備份，自動移進 `備份/更舊的/`。
- 若不用腳本手動做，也要遵守上面同樣的規則。

### 3. 更新要求清單
- 檔案：`納可要求清單.txt`
- 使用者給的每個指令都要先登記成一條。
- **還沒做完的，放在檔案最前面（最上面）。**
- **做完的，移到檔案最後面（最下面），並在該條前面標記 `✗`**（表示已完成/已劃掉）。

### 4. 存到 GitHub（雲端環境特別重要）
- 這是雲端環境，只有 push 到 GitHub 的東西才會保留，本機資料夾會被回收。
- 所以每次更新後（含備份資料夾），都要 `git add -A`、commit、push 到指定分支。

---

## ⭐ 穩定版 vs 開發中（GitHub Pages 上線規則）

GitHub Pages 會把 `main` 分支**根目錄**的內容變成公開可玩的網頁；玩家點的就是這個。
所以：

- **根目錄 = 穩定版（會被玩家玩到）**：只放已經完工、測過的功能。
  - 目前的玩家都是納可的朋友測試員，所以**作弊選單要保留**（跳教學／通關第一層／全體升等等）。
- **`開發中/` 資料夾 = 還沒完工的東西**：新功能先在這裡做、在這裡測。
  - `開發中/` 是一份可獨立執行的完整遊戲（有自己的 index.html／style.css／js／），
    要預覽時開 `開發中/index.html` 或 Pages 的 `.../開發中/` 路徑。
  - 功能真的做完、測好，才「整包」複製覆蓋到根目錄，成為新的穩定版。
- **推送位置**：直接 commit / push 到 `main`（納可已開好權限）。穩定版與開發中都在 `main`，
  用資料夾區分，不用另開分支。
- 根目錄有 `.nojekyll`，確保 Pages 原樣提供所有檔案（含中文檔名/資料夾）。

判斷準則：**會不會讓「正常玩」的玩家碰到半成品？** 會 → 放 `開發中/`；不會且已完工 → 根目錄。

## 專案技術備註

- 純前端遊戲（HTML + CSS + 原生 JavaScript），無框架、無建置流程。
- 直接用瀏覽器打開 `index.html` 就能執行；改完重新整理瀏覽器即可看到結果。
- 檔案結構與系統說明見 `README.md`。
- 改程式前先讀對應檔案開頭的區塊註解（原作者的中文註解很詳細）。
